# Milestone 3: AT Protocol Writer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `multikey-java`, `quarkus-did` and the `quarkus-atproto` train (syntax, identity, Lexicon codegen + validation, XRPC client, OAuth client, core and Standard.site packs) so a Quarkus app signs a user in with AT Protocol OAuth (login or link mode) and writes a `site.standard.document` to their PDS.

**Architecture:** Three new git repos beside the existing ones. `multikey-java` is plain Java (BouncyCastle optional, for secp256k1 only). `quarkus-did` is a Tier 1 extension with a `DidMethod` SPI. `quarkus-atproto` is a multi-module Tier 2 repo: plain `atproto-syntax` and `atproto-lexicon-codegen`, Quarkus extensions for identity, lexicon, xrpc and oauth, two lexicon packs that ship JSON plus classes generated at pack build time, a `test` module of fake AT Protocol servers, and a sample app. The OAuth client is implemented from scratch (no `quarkus-oidc`) and integrates through Quarkus Security.

**Tech Stack:** Java 21, Maven, Quarkus 3.40.1, Vert.x (routes, DNS client), Jackson, Mutiny, Caffeine, JDK EC/EdDSA crypto, BouncyCastle (optional), JUnit 5 + `QuarkusUnitTest`, REST Assured, Awaitility.

**Spec:** `docs/superpowers/specs/2026-10-26-milestone-3-atproto-writer-design.md` (the design, binding) and `Quarkus Open Web Extensions — Architecture Spec.md` (conventions).

## Global Constraints

- Java 21; Quarkus `3.40.1`; Apache 2.0; groupId `org.sitenetsoft.quarkus`; version `0.1.0-SNAPSHOT` in all three repos.
- Packages: `org.sitenetsoft.multikey`, `org.sitenetsoft.quarkus.did`, `org.sitenetsoft.atproto.syntax`, `org.sitenetsoft.atproto.lexicon.codegen`, `org.sitenetsoft.quarkus.atproto.{identity,lexicon,xrpc,oauth}`, `org.sitenetsoft.quarkus.atproto.test`.
- Config prefixes: `quarkus.did.*`, `quarkus.atproto.identity.*`, `quarkus.atproto.lexicon.*`, `quarkus.atproto.xrpc.*`, `quarkus.atproto.oauth.*`. Logging categories match the package.
- Every extension module: `quarkus-extension-processor` annotation processor, runtime `quarkus-extension-maven-plugin` (`extension-descriptor`), `META-INF/quarkus-extension.yaml` (status `experimental`), `quarkus-skill.md`, Dev UI card where the design names one.
- `@ConfigMapping` roots; build-time and runtime separate; defaults only via `@WithDefault`. Blocking `Foo` + Mutiny `ReactiveFoo`; SPI defaults `@DefaultBean`; multi-implementations via `@All List<T>`; SPI types unremovable.
- Every outbound HTTP call through `quarkus-safe-fetch` (`SafeFetchClient`/`ReactiveSafeFetchClient`, `send`/`get`/`post`). Never block the Vert.x event loop.
- Never log access/refresh tokens, authorization codes, DPoP private keys, client assertions or signature values.
- Server routes are Vert.x `RouteBuildItem`s at the server root via `HttpRootPathBuildItem.routeBuilder()`, warning when `quarkus.http.root-path` is not `/` (Milestone 1–2 pattern).
- Parent POMs copy `quarkus-webfinger/pom.xml` (BOM import, extension processor, surefire `-XX:TieredStopAtLevel=1` and `java.util.logging.manager`). CI copies `quarkus-activitypub/.github/workflows/build.yml` (sibling clones; native job with Mandrel **25** and `-Dquarkus.native.additional-build-args=-J-XX:TieredStopAtLevel=1,--parallelism=8`, `-pl integration-tests -am` where a sample app exists).
- Host rules: `JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64`; Maven `-T 8` max; one Maven build at a time; before every build check `pgrep -f "^[^ ]*/bin/java .*plexus-classworlds"` (not `pgrep -f maven`, which matches the shell wrapper) and wait until it is empty; logs never under `/tmp`.
- Build order: `multikey-java` → `quarkus-did` → (`quarkus-safe-fetch` already installed) → `quarkus-atproto`.
- Fixtures fetched from the network (Standard.site records, `com.atproto` lexicons, syntax interop files) are committed as files with their source and fetch date in a README; tests never hit the network.

## Review Focus

1. **Handle typed with `@`, uppercase or a trailing dot at login** (`@Alice.bsky.social.`): normalise (strip leading `@`, trailing `.`, lowercase) before validation; a reasonable user expects it to work. Test in Task 6.
2. **The PDS rotates its DPoP nonce mid-session** (a resource request that worked once now answers 401 `use_dpop_nonce`): retried transparently once, nonce stored per server. Test in Task 13.
3. **Two concurrent requests both find the access token expired**: exactly one refresh reaches the authorization server; both requests succeed. Test in Task 13.
4. **The user denies consent** (callback carries `error=access_denied` with a valid `state`): pending entry deleted, no session, 401 (or the error page) with the reason, never a 500. Test in Task 13.
5. **A title exactly at and one over `maxGraphemes` 500 with multi-codepoint emoji** (`👩‍💻` counts as one grapheme): 500 passes, 501 fails; byte-length limits counted in UTF-8. Test in Task 9.

### Task 2: JWK, PEM, thumbprints and signatures

**Files:** `src/main/java/org/sitenetsoft/multikey/{Jwk.java,Pem.java,JwkThumbprint.java,Signatures.java,Algorithm.java,KeyPairs.java}`; tests `JwkTest`, `PemTest`, `JwkThumbprintTest`, `SignaturesTest`.
