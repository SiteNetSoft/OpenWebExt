# Milestone 2: deferred findings and rulings

Extracted from the execution ledger on 2026-10-25 after the final review. Every item below was reviewed and deliberately deferred; the final reviewer judged none of them merge-blocking. Rulings are decisions made on the user's behalf during execution.

## Rulings

- Ruling: Tier 1 repos get a `milestone-2` branch for Tasks 1–2; the new quarkus-activitypub repo starts on main — Milestone 1 committed directly to main in every sub-repo and the repos have no remote, so a branch in a brand-new repo isolates nothing; a branch in the Tier 1 repos keeps their main at the Milestone 1 state — cost if wrong: a merge step the user must do (trivial).
- | Task 7 ↔ Task 8–12 | ActivityPubUrls, stores, FollowerStore.add(local, remote, remoteInbox, state, followId), TransactionRunner | consistent; design listed add() without inbox — plan adds it (Ruling below) |
- Ruling: FollowerStore.add carries the follower's inbox (design omitted it) — avoids a fetch per delivery and lets followerInboxes work offline — cost if wrong: one extra column.
- Ruling: no test asserts nothing; no verbatim duplication mandated. Scan clean otherwise.
- Ruling: fluent setters keep returning ASObject; Task 5 vocabulary classes add covariant overrides only where their own tests chain subclass-specific setters, no self-type generic — keeps the model simple for Kotlin/Java users; cost if wrong: some verbose casts in app code.
- Ruling: ObjectOrLink record components are `Ref(URI href)` and `Embedded(ASObject value)` (brief's `uri`/`object` names collide with the interface's Optional accessors).
- Ruling: PublicKey sets no default `type` (Mastodon's key object is untyped; a default would break lossless round-trip) — cost if wrong: none for interop.
- Ruling: Task 5 had no true RED run (implementation written before first test run); accepted since the forced-failure check and 55 passing tests show the tests discriminate — cost if wrong: a weak test slipping through, caught by later integration tests.
- Ruling: add runtime `quarkus.nodeinfo.protocols` (Optional<Set<String>>) so NodeInfo works alone; WARN when the merged document has no protocols — plan gap; cost if wrong: one extra config key.
- Ruling: NodeInfoContributors apply in ascending @Priority order with "contribution wins when present", so the highest priority has the final say (the plan's "highest first" wording contradicted its own test); Task 8's ActivityPubNodeInfoContributor @Priority(100) therefore runs last and its values win — cost if wrong: contributor ordering surprises, documented in javadoc/README.
- Ruling: ObjectStore.outbox/outboxCount return public local activities only (design: outbox page lists public activities); Hibernate store must match — cost if wrong: followers-only posts absent from the outbox collection, which is what Mastodon does too.
- Ruling: pages are 1-based; follower/following lists and counts include only ACCEPTED; oldestPending by created; host() omits default ports.
- Ruling (Task 8 dispatch): the eight `quarkus.activitypub.paths.*` templates move to the build-time config root (same property names) so the processor can register routes from them; `base-url` stays runtime — Vert.x routes are fixed at build time; cost if wrong: path layout cannot be changed without a rebuild (acceptable; Mastodon-compatible defaults).
- Ruling (Task 8 dispatch): `*/*` alone does not count as an ActivityPub Accept (browsers send it); only application/activity+json and application/ld+json do.
- Ruling (Task 8 dispatch): ActivityPubContentNegotiation resolves the object id as base-url + request path, not the raw Host header.
- Ruling: model-level scalar output for one-element lists on url, attributedTo, inReplyTo, icon, image (ASObject) and publicKey (Actor); to/cc/bto/bcc/audience/tag/attachment/items/orderedItems/alsoKnownAs stay arrays; the actor-only tree rewrite is removed — Mastodon's value_or_id raises on arrays for these; cost if wrong: strict consumers that demand arrays (none known) would need the list form.
- Ruling: the negotiation helper calling next() for missing or private objects is accepted (indistinguishable from the caller's view, no leak).
- Ruling: third Tier 1 change — safe-fetch `FetchResponse` gains a leading `URI uri` component (final URL after redirects) with a compatibility constructor; ActivityPub fetches compare the document id against the final host AND refuse cross-host redirects (FETCH_FAILED) so signed headers never follow one — cost if wrong: a legitimately migrated server that redirects to a new domain is not followed (apps use the `Move` / alsoKnownAs path instead).
- Task 9: parked (security, deferred to the final fix wave) — Ruling: after a cross-host redirect safe-fetch still re-sends caller headers (our Signature/Date) to the other host; the signature cannot verify there but could be replayed against the original URL within max-age (impact: a GET as our instance actor of a document that is public anyway). Fix in safe-fetch: drop caller-supplied headers on a cross-host hop (browser Authorization semantics). Carried to the final review's fix wave.
- Ruling: dedup is skipped when an activity id's host differs from the signer's host (prevents cross-actor dedup poisoning) — folded into fix round 1 as a one-line check; cost if wrong: duplicate processing of oddly-hosted ids (harmless).
- Ruling: `ActivityPub` and `ReactiveActivityPub` cannot share one class (publish differs by return type only); Task 11 ships `ActivityPubImpl` (blocking) and `ReactiveActivityPubImpl` over one core — plan text amended.
- Ruling (Task 11): FollowerStore gains `FollowRelation` + `follower(local, remote)` / `followingRelation(local, remote)` (and reactive twins) so accept/reject/undo can read back the stored follow id and a pending follower's inbox — Task 12's Hibernate store must implement them; cost if wrong: two extra SPI methods.
- Ruling (Task 11): a host with no recorded success is not "dead" (otherwise a brand-new host failing 5 times in one poll would have new deliveries given up immediately); dead = lastSuccess present and older than dead-after, with a recent failure.
- Ruling: "publish inside inTransaction" covers the store writes only; recipient/actor fetches are pre-resolved before the transaction opens (RecipientResolver split into prefetch + pure resolve; same for follow/undoFollow/delete/undo/answerFollow) — a JTA transaction must never span remote HTTP; cost if wrong: a recipient fetched before the transaction could change between prefetch and resolve (negligible).
- Ruling: ActivityPubImpl.delete refuses non-local objects and objects not attributed to the deleting actor (folded into fix round 1; local data-loss bug).
- Ruling (Task 12 dispatch): the carried inbox-transaction concern is fixed in Task 12 — the selected InboundActivityHandler gets a `prepare` hook run outside the transaction (FollowHandler fetches the follower actor there), `handle` runs inside; test in the hibernate module — cost if wrong: one extra SPI method with a default no-op.
- Ruling (Task 12 dispatch): entities register in the default persistence unit only for this milestone; a named PU is documented as unsupported unless wiring is trivial.
- Ruling (Task 12): the inbox seen-marker cannot be rolled back atomically (markSeen runs before the 202); `ObjectStore.forgetSeen` compensation on processing failure is accepted — cost if wrong: a crash between markSeen and forgetSeen drops one activity until the sender retries with a new id.
- Ruling (Task 13): ActorStore.list(int) added to the SPI (Dev UI needs an actor listing); counts above 200 shown as "200+" — accepted; cost if wrong: one extra SPI method.
- Ruling: instance actor stays at the actor template (`/users/instance`) rather than the design's `{base-url}/actor` — one URL scheme, one handler; documented; cost if wrong: a cosmetic URL difference.
- Ruling: 401/403 after double knocking stays retryable with backoff rather than FAILED — remote key caches go stale after rotation and recover; cost if wrong: a host rejecting one actor can get paused for all (already a deferred minor).
- Ruling: the parked safe-fetch cross-host header forwarding is fixed in this wave (drop caller-supplied headers, Host included, on a cross-host hop) — credential-forwarding class; small change.
- Ruling: #8 residual is load-bearing (native actor documents would lose inbox/publicKey) and a one-line change, so the same fixer adds `Actor.class` + a NativeReflectionTest assertion; the controller verifies the hunk by reading it — cost if wrong: none beyond one extra commit.
