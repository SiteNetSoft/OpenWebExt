## Rulings (decision — cost if wrong)

- Ruling A: Task 4 scaffolds `xrpc/api` (artifact `atproto-xrpc-api`, plain + Mutiny) in the module list; Task 8 fills its interfaces — plan omission; cost if wrong: none.
- Ruling B: Task 7 fetches the `com.atproto` and Standard.site Lexicon JSON itself (network allowed at dev time, committed with source/date) into its test resources; Task 8 copies the same files into the packs — task order; cost if wrong: one duplicate fetch.
- Ruling C: Task 8 creates the runtime support types `AtprotoRecord`, `BlobRef`, `CidLink` in `lexicon/runtime` (needed by generated pack code); Task 9 adds the registry, validator and app codegen around them — dependency order; cost if wrong: none.
- Ruling D: packs depend on `quarkus-atproto-lexicon` runtime (support types) and `atproto-xrpc-api` only, never on `quarkus-atproto-xrpc` runtime — avoids the xrpc↔core-pack cycle; cost if wrong: none.
- Ruling: CI sibling install order is multikey-java → quarkus-safe-fetch → quarkus-did (the plan's order omitted that quarkus-did depends on safe-fetch) — cost if wrong: none.
- Ruling: plain libraries use `org.sitenetsoft.atproto.syntax` and `org.sitenetsoft.atproto.lexicon.codegen` (design); the Task 4 scaffold's package-infos used `org.sitenetsoft.quarkus.atproto.*` for them — renamed in Task 5 before review; extensions, `xrpc.api` (`org.sitenetsoft.quarkus.atproto.xrpc.api`), packs and `test` keep `org.sitenetsoft.quarkus.atproto.*` — cost if wrong: a package move later.
- Ruling: generated code references `org.sitenetsoft.quarkus.atproto.xrpc.api.ReactiveXrpcClient` (the plan's Task 7 text said `...xrpc.ReactiveXrpcClient`; the interface lives in the api module per Ruling A) — cost if wrong: none.
- Ruling: Handle.parse rejects disallowed TLDs; Handle.isValidSyntax accepts the interop fixture's valid list (which includes .local/.arpa/.onion); NSID authority 253-char limit not enforced because the official fixture exceeds it — fixtures are the conformance authority; cost if wrong: an over-long NSID authority accepted.
- Ruling: the test-only `quarkus.atproto.identity.https-well-known-override` (Map<String,URI>) is built in Task 6, not Task 11 — Task 6's own tests need it; cost if wrong: none.
- Ruling: conflicting DNS `did=` records fail the handle even when HTTPS answers (atproto.com spec wording) rather than falling back to HTTPS as the TS reference does — cost if wrong: a misconfigured-DNS account can't sign in until DNS is fixed.
- Ruling: on a transient reverse-check failure resolveDid returns the identity with handle.invalid for that call only (not cached), rather than failing — the OAuth sub→PDS step must survive a DNS blip; cost if wrong: one login shows handle.invalid until the next resolution.
- Ruling: Lexicon `bytes` → runtime value type `org.sitenetsoft.quarkus.atproto.lexicon.Bytes` owning its `{"$bytes": base64}` form (created for real in Task 8 with BlobRef/CidLink/AtprotoRecord) — a global byte[] serializer would change the app's REST JSON; cost if wrong: one wrapper type in app code.
- Ruling: optional+nullable Lexicon properties generate plain nullable T (absent and explicit null both → Java null; null omitted on write); typed records cannot send an explicit JSON null (e.g. putRecord swapRecord "must not exist") — callers use the generic XRPC client with a JsonNode body for that — YAGNI, only one field in our packs; cost if wrong: a tri-state type added later.
- Ruling: generated record and object types preserve unknown JSON properties (any-setter/any-getter map, $type on plain refs included); round-trip tests use real records that carry extra fields — Lexicons are open and evolve; losing another app's data is unacceptable; cost if wrong: a slightly heavier generated API. Dispatched to the Task 8 implementer before review.
- Ruling: the committed real record `document-visibility.json` (array `content` where the Lexicon declares a union) stays and is asserted invalid — the validator follows the published Lexicon, not one app's data; cost if wrong: our writer refuses to re-write such a record in validate=true/optimistic mode.
- Ruling: RecordsImpl.forRepo is an instance method on the injectable bean with a WriteGuard overload (plan said package-public factory) — OAuth injects it and passes a per-session scope guard; cost if wrong: none.
- Ruling: the client metadata and JWKS routes are served under quarkus.http.root-path (runtime-configurable paths need runtime route registration); a WARN tells operators to include the root path in client-base-url — unlike /.well-known routes, the client_id is an arbitrary URL that only has to match itself; cost if wrong: one config line.
- Ruling: client assertions carry `exp` = iat + 60 s (RFC 7523 requires it; the brief omitted it).
- Ruling: every AS endpoint must be https (http only when safe-fetch https-only=false) and on the issuer's origin — the AT Protocol profile co-locates them; cost if wrong: an AS that splits endpoints across origins is refused.
- Ruling: the configured fallback scope is included in the client metadata `scope` (the AS refuses scopes not registered) — cost if wrong: the registered scope is broader than the primary request.
- Ruling: AtprotoRoleMapper is additive (default mapper always gives `user`; app mappers add roles) rather than replace-by-presence — matches the "add to behaviour" hook pattern; cost if wrong: apps can't remove `user`.
- Ruling: a bare host input is treated as a handle; entryway/server logins need a URL (https://host) — handles and hosts are syntactically identical; cost if wrong: typing `bsky.social` tries handle resolution first and fails with a handle error.
- Ruling: XRPC resends at most once; a call hitting a missing nonce and a server-expired token together fails once (the next call succeeds) — keeps the no-loop guarantee; cost if wrong: a rare single failed write that the app may retry.
- Ruling: login is bound to the browser with a short-lived HttpOnly SameSite=Lax binding cookie whose hash is stored in the pending entry and checked (constant time) before the pending entry or any existing session is touched — RFC 9700 §4.7.1; cost if wrong: a browser that blocks the cookie can't log in.
- Ruling: the refresh authority check (DID → PDS → AS issuer) runs before spending the refresh token; transient failures fail the call retryably and keep the session; definitive failures delete the session without spending; after the response sub must equal the DID — a DNS/PLC blip must not log users out; cost if wrong: a tiny window where authority changes between pre-check and refresh (sub is still verified).
- Ruling: one OAuth login in flight per browser (a second tab's login invalidates the first one's binding cookie) — accepted and documented; cost if wrong: a confusing 401 for multi-tab logins.
- Ruling (Task 14 dispatch): in link mode the pending entry records the app principal at login and the callback requires the same principal (on top of the browser binding cookie), so a link can't attach to a different app user — cost if wrong: an app user who re-authenticates as someone else mid-flow gets a 401.
- Ruling (Task 14 dispatch): AtprotoSessions picks the most recently created live session when a DID has several — cost if wrong: background writes use a different browser's session (same account, same scope rules).
- Ruling: the login endpoint accepts only a same-origin POST in both modes (Sec-Fetch-Site same-origin, else Origin == the app's origin, else refuse); GET → 405 — supersedes the design's "GET|POST login"; the design text is amended at the end of the milestone — cost if wrong: a plain link can't start a sign-in (apps use a form or a button).
- Ruling: link-mode AtprotoUser gets a non-blocking resolve path cached per request; synchronous accessors fail fast on the event loop with non-default stores — cost if wrong: one extra API method.
- Ruling (Task 15): the packaged-app ITs use a confidential client (generated key, the fake AS fetching client metadata from the app) instead of the dev client — @QuarkusIntegrationTest runs in NORMAL launch mode where the dev client and identity override are refused by design; this exercises the production path; cost if wrong: the dev client is covered only by the QuarkusUnitTest suites.
- Ruling (Task 15): handles in the packaged ITs resolve through a FakeDns server in quarkus-atproto-test set as quarkus.atproto.identity.dns.servers (no test-only TxtResolver bean in the sample).
- Ruling (Task 15): `lexicons` aggregator added to the root reactor (its parent POM was never installed); the iat ±61 s flake fixed to ±90 s (Task 11 deferred minor, done here).
- Ruling: the atproto authentication mechanism ranks above basic auth for challenges (priority 3000) — login-mode apps that also use basic auth must not prompt for a password that can never work; cost if wrong: a basic-only app path gets the atproto challenge (null challenge in link mode, so unaffected there).
- Ruling: app-generated Lexicon types are registered for native reflection now rather than deferred — the design promises app Lexicons work and the fix is cheap; cost if wrong: none.
- Ruling: final whole-branch review run as two parallel Opus reviewers (A: OAuth/XRPC/sample/docs/CI; B: multikey/did/identity/syntax/lexicons) — the Fable dispatch failed (usage credits exhausted, HTTP 429) — cost if wrong: a cross-cutting issue spanning both halves could fall between them.
- Ruling: link-mode callback without an app identity answers a same-origin bounce (meta refresh to itself + marker) before taking the pending entry, so SameSite=Strict app cookies (Quarkus form auth default) arrive — cost if wrong: one extra redirect per link sign-in.
- Ruling: refresh across nodes uses an optional lease method on the session store SPI (default = single-node); docs no longer promise exclusive spending without it — cost if wrong: SPI grows by two default methods.
- Ruling: record keys are validated against the Lexicon `key` type before create(rkey)/put — cost if wrong: an app relying on slug keys for a `tid` collection must switch to TIDs.
- Ruling: final fix wave folds in A-M1, A-M2, A-M3, A-M4, A-M6, A-M8 (skill/IT docs), B-M1, B-M2, B-M4, plus deferred Task 13 handle-downgrade and Task 15 reflection-holder naming; defers A-M5 (double metadata fetch), A-M7 (safe-fetch origin compare — Milestone 2 repo), B-M3 (`uri` format strictness vs java.net.URI — interop read failure on others' records), B-M5 (signing key unparsed; legacy blobs) — cost if wrong: those four remain as documented follow-ups.
